# x402

**Type:** HTTP payment protocol / stablecoin rail
**One-line:** An open standard that embeds stablecoin micropayments directly into HTTP, using the long-reserved 402 status code to let any API or service request payment per request.

## How it works

When a client (human or agent) hits an x402-enabled endpoint without payment, the server returns an HTTP 402 response describing what payment is required. The client's x402-compatible library automatically signs a payment authorization with a connected wallet, resubmits the request, and the server verifies and settles on-chain. No accounts, sessions, or API keys required — payment is the authentication.

## Settlement speed & cost

- Settles on-chain via stablecoin (primarily USDC)
- Zero protocol fees beyond nominal network gas
- Designed for sub-cent micropayments at high frequency

## Who controls it

Built by Coinbase, open-source at [coinbase/x402](https://github.com/coinbase/x402). The x402 Foundation was launched with Coinbase and Cloudflare. Governance is evolving.

## Agent-friendliness

Very high. x402 is purpose-built for agents: no human login flow, payment is fully programmable via wallet signing, and the HTTP-native design means any agent making web requests can pay without additional tooling.

## Supported chains

Base (primary), Polygon, Arbitrum, Solana, Ethereum, World

## Regulatory status

Unresolved. Existing financial regulations assume human-decisioned transactions. x402 agent payments raise open questions about authorization, liability, and money transmitter licensing.

## Governance concern (April 2026)

Agentic.Market (x402 discovery marketplace) hosts unauthorized third-party wrappers of APIs whose ToS explicitly prohibit reselling — including Wolfram Alpha, Amadeus, and formerly Google Flights. The protocol has no visibility into whether upstream data was obtained with authorization. Google Flights endpoint removed April 25, 2026. See [[x402-governance]] for full analysis.

MPP marks first-party integrations with a green circle on each service card — a model x402 ecosystem currently lacks.

Exa went first-party on x402 (April 7, 2026), citing Linux Foundation governance as the reason.

## Open questions

- How does KYC/KYA work at scale for 519K+ buyers?
- Will x402 develop a provenance/authorization layer to address the unauthorized wrapper problem?
